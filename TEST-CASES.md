# TEST-CASES.md: edge cases and what the app does

Sharad Utsav 2026 booking. Each row is a situation a real family (or a bad actor) can walk into, what the app does about it, the file that enforces it, and the test that pins it. Test files are under `tests/`; "manual" rows say how to reproduce them by hand. Decision numbers (D1-D16) refer to `docs/plans/2026-11-24-sharad-utsav-booking.md` and the README "Decisions I made".

Run the automated ones with `npm test`. Many rows are cases the brief never mentioned; the decision behind each is in the README under "Decisions I made".

## Not handled (on purpose)

- **Festival already over (today is 24 Nov 2026).** No sales cutoff, on purpose, so reviewers can use the live site (D13). Real use needs a cutoff date per festival.
- **Age is self-declared.** The server cannot know that "11" is really 12. Rules and prices follow the declared age; the door volunteers are the check. Age is measured as a whole number on 10 Nov, with no date of birth, so a child who turns 12 mid-festival stays a child (D9).
- **Same person listed twice under different ids.** Two rows with the same name and age are allowed (twins exist). The cost of the doubt is one extra ticket the family pays for.
- **Email and phone are not verified, and no confirmation email is sent.** The confirmation lives on screen and at the #booking link. Needs an email provider.
- **Real payment.** Payment is simulated (test card 4242... approves, 4000 0000 0000 0002 declines). Real Stripe would authorise, commit, then capture (ADR-0006).
- **Cancel, refund or edit after booking.** Not built. A booking is final once confirmed.
- **Holding stock while someone types.** No cart hold: stock is only taken at the moment of payment. A person can see "available" and still meet a 409 at the end.
- **Rate limiting and bot protection.** Left to the platform; no per-IP throttle in the app.
- **Garba places per session.** One shared pool of 2 across Nov 11 and 13 (D5). No per-session split.
- **Name content.** Not screened for profanity or odd Unicode. React escapes everything on screen, so HTML typed into a name is shown as text, not run.
- **Manual rows were not run in an automated browser.** Everything marked "manual" says how to reproduce it; automated rows are run by `npm test`.

## Found while testing

None of these change what anyone is charged. Production code was not touched while writing this list.

- **The "All-Day Child Pass is cheaper" hint recommends a pass that may be sold out.** Hints are built from the static catalog (initialStock), not live inventory. With allday-child at 0 and a child on 5 Day Passes, the hint still says an All-Day Child Pass ($30) is cheaper; the same static check keeps saying "All-Day Adult is sold out" even if stock is added later. The stock check still blocks the purchase, so no money is wrong; the advice is. Pinned as a known failure: edge-cases.test.ts › does not recommend an All-Day Child Pass that is sold out right now (it.fails). Fix: pass inventory into the hint step.
- **Family Pass hints print a raw date.** "... on 2026-11-11 ..." appears in the hint text instead of "Wed, Nov 11". Cosmetic. Pinned as a known failure: edge-cases.test.ts › says the Family Pass hint with a readable date, not 2026-11-11 (it.fails). Fix: format with the same day label helper the UI uses.
- **A phone number with no digits passes validation.** "-------" or "(((((((" matches the character class and length check, though the message says digits. Contact detail is useless but harmless to money. Pinned as a known failure: edge-cases.test.ts › rejects a phone number that has no digits (it.fails). Fix: also require 7+ digits.
- **SEVA10 rounding can never show up with this catalog.** Every price is a whole number of dollars, so 10% is always a whole number of cents. The half-up rounding is tested but only reachable if prices change. No action needed.
- **The booker does not count as a supervisor unless attending (D8).** A non-attending booker aged 40 cannot "sponsor" a group of children who arrive with a 17-year-old. Intended (the door needs an 18+ present), but surprising to a parent. Worth a clearer message if the committee agrees.
